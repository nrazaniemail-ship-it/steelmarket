# گزارش پیاده‌سازی لایه‌بندی فولادبان ۱.۴

## مرجع طراحی
ساختار تجربه کاربری با بررسی مخزن واقعی `nrazaniemail-ship-it/namello-1-0-2` و قراردادهای رابط آن، به‌ویژه `tests/settings-contract.test.mjs` و `CHANGELOG-SOURCE.txt` طراحی شده است. هدف، انتقال الگوی ناوبری و سازمان‌دهی تنظیمات به فولادبان است؛ نه انتقال هویت یا محتوای اختصاصی ناملو.

## لایه‌های اصلی
1. **داشبورد** — خلاصه وضعیت، شاخص‌ها و محصولات تحت رصد
2. **محصولات** — ثبت/ویرایش محصول، انتخاب فهرست استاندارد و سبد منتخب
3. **مراجع قیمت** — سلامت منابع، فهرست منابع و اولویت‌بندی
4. **تحلیل بازار** — شاخص‌های بازار، مقایسه قیمت، نمودار و رویدادها
5. **تنظیمات** — کارت‌های مستقل و جمع‌شونده

## ساختار لایه تنظیمات
- **ظاهر برنامه و رنگ‌بندی:** پوسته روشن/تیره/سیستم، رنگ تأکیدی، رنگ زمینه صفحه و رنگ آیکون‌ها
- **تنظیمات پایش و اتصال داده:** همان کنترل‌های موجود برای پایش خودکار، فاصله بررسی، API، توکن نشست، نرخ ارز و اعلان‌ها
- **قالب نمایش:** حالت راحت یا فشرده
- **ترتیب لایه‌ها:** جابه‌جایی لایه‌ها با فلش‌های بالا/پایین نارنجی و ذخیره ترتیب
- **دفترچه راهنما:** راهنمای مختصر کاربرد هر لایه
- **داده‌ها و خروجی:** دسترسی سریع به CSV و بررسی قیمت‌ها
- **درباره برنامه:** معرفی و نسخه برنامه

هر کارت تنظیمات به‌صورت مستقل باز و بسته می‌شود. تنظیمات رابط کاربر با کلید `fooladban.ui.v1` ذخیره می‌شوند؛ کاتالوگ بازار و انتخاب محصولات در فضای ذخیره‌سازی مستقل خود باقی می‌مانند. تنظیمات قبلی پایش، محصولات، سوابق و API پاک یا بازنویسی نشده‌اند.

## رفتار واکنش‌گرا
- نمایشگر بزرگ: نوار ناوبری افقی زیر سربرگ
- موبایل: نوار ناوبری ثابت پایین صفحه با رعایت safe-area
- محتوای هر لایه مستقل نمایش داده می‌شود؛ پنل‌های قبلی در لایه مقصد قرار گرفته‌اند تا شناسه فرم‌ها و منطق پردازش حفظ شود.

## فایل‌های تغییر یافته
- `core/app-shell.js` — ساخت لایه‌ها، ناوبری، تنظیمات و ترتیب قابل‌تغییر
- `index.html` — پوسته بصری، استایل و بارگذاری ماژول
- `sw.js` — کش آفلاین ماژول‌های جدید
- `.github/workflows/test.yml` — بررسی syntax ماژول جدید
- `tests/browser.smoke.cjs` — آزمون ناوبری، کارت‌های تنظیمات، تغییر تم و مدیریت محصول
- `README.md` و `package.json` — مستندات و نسخه ۱.۴

## وضعیت اعتبارسنجی
اجرای CI پس از آخرین تغییرات لازم است کامل شود. تا زمان مشاهده نتیجه موفق workflow و استقرار GitHub Pages، این گزارش به معنی تأیید نهایی روی دستگاه واقعی نیست.
