# راه‌اندازی نسخه وب فولادبان

## محدوده فعلی
تا زمان تکمیل و پذیرش نسخه وب، توسعه و انتشار فقط روی PWA وب انجام می‌شود. گردش‌کار Android صرفاً با اجرای دستی قابل اجراست و روی هر Push اجرا نمی‌شود. ساخت iOS نیز به مرحله پس از تثبیت نسخه وب موکول است.

## انتشار خودکار با GitHub Pages
1. در مخزن GitHub وارد Settings → Pages شوید.
2. در بخش Build and deployment، گزینه Source را روی GitHub Actions قرار دهید.
3. در صورت نیاز، مجوزهای Actions را در Settings → Actions → General طوری تنظیم کنید که workflow مجاز به انتشار Pages باشد.
4. هر commit واجد شرایط روی main، workflow انتشار وب را اجرا می‌کند.
5. آدرس نهایی در اجرای موفق workflow با نام Deploy Fooladban to GitHub Pages نمایش داده می‌شود.

Workflow: `.github/workflows/pages.yml`

## انتشار وب و اتصال داده زنده
GitHub Pages فقط فایل‌های استاتیک PWA را میزبانی می‌کند. برای دریافت داده از سایت‌های قیمت و ذخیره تاریخچه مرکزی باید سرویس Cloudflare Worker و D1 جداگانه Deploy شوند. مراحل پیکربندی در `workers/wrangler.toml` و `docs/IMPLEMENTATION_REPORT_R1_R2.md` آمده است.

تا قبل از تعریف منابع واقعی، مجاز و تست‌شده، قیمت زنده را نباید به‌عنوان داده معتبر نمایش داد. نرخ ارز خارجی نیز باید از منبع/اپراتور معتبر دریافت و همراه زمان به‌روزرسانی ثبت شود.

## معیار اتمام نسخه وب
- رابط واکنش‌گرا و RTL روی موبایل و دسکتاپ
- افزودن/ویرایش/حذف منابع و محصولات
- مقایسه فقط برای مشخصات، واحد، ارز، مالیات و تحویل هم‌مبنا
- تاریخچه قابل ممیزی و نشانگر داده کهنه/خطادار
- اعلان‌های وب با اجازه صریح کاربر و تست در مرورگرهای پشتیبانی‌شده
- پایداری آفلاین PWA و مدیریت خطای شبکه
- تست خودکار، تست مرورگر واقعی و پذیرش کاربری
- راه‌اندازی Worker/D1 و مشاهده حداقل یک منبع واقعی مجاز در محیط عملیاتی

## مرحله موبایل پس از پذیرش وب
- Android: همگام‌سازی نهایی پوسته WebView/PWA، تست دستگاه، امضای release و تولید APK/AAB.
- iOS: بسته‌بندی با Xcode روی macOS، تنظیم signing/provisioning، تست Safari/WebKit و تولید IPA/TestFlight. ساخت IPA صرفاً از runner لینوکس ممکن نیست.
- هر دو کلاینت باید از API و قرارداد داده مشترک استفاده کنند؛ منطق تجاری نباید دو بار پیاده‌سازی شود.
